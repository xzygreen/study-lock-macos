# 认真 (StudyLock)

一款帮助认真学习的 macOS 原生应用:展示时间,并在专注期间隐藏白名单之外的全部应用。

## 功能

- **三种专注模式**
  - 倒计时:25 / 45 / 60 / 90 分钟,到点自动解锁
  - 正计时:持续锁定并累计专注时间,手动结束
  - 番茄钟:专注 → 休息自动循环(时长、轮数可调),休息期自动解锁,下一轮自动重新锁定
- **定时课程表**(v2.5):按固定时段自动开启倒计时专注、时段间隙自动解锁(默认 9:00-18:05 共 7 节,可增删改);星期开关(默认周一~周五)+「跳过日期」(节假日)与「补班日期」(调休周末)自定义;中途打开应用立即锁定至本时段结束;提前结束(走冷静期+确认短语)后该时段当天不再自动重启;不打断已有手动会话,其结束后自动接上
- **隐藏式锁定**:非白名单应用一被激活立即隐藏并弹回专注界面;应用不会被关闭,数据安全,解锁后自动恢复原样
- **退出摩擦力**(v2.1)
  - 提前结束先过**冷静期**(10 秒起,近 7 天强退越多越长,最高 60 秒),随时可反悔继续专注
  - 之后需一字不差输入**动态生成的确认短语**(含当前时间与已专注分钟,杜绝肌肉记忆秒退)
  - 强制退出(Cmd+Opt+Esc)会被记录为「污点」:下次启动显示强退通告、未完成的会话自动恢复锁定(或补记一条强退记录),并加长后续冷静期
- **网站白名单**(v2.4):锁定期间每 2 秒检查所有已打开浏览器(Safari/Chrome/Edge/Arc/Brave/Vivaldi,含 Beta/Dev/Canary 各渠道)的每个标签页,不在允许列表的网页立即清空为空白页(含后台标签);工作在浏览器层,兼容任何代理/VPN(含 Clash TUN、WARP),无需改动网络设置。子域名自动包含
- **使用时长明细与报告**(v2.2+):专注期间统计前台应用与网站时长、被拦网站,写入每条记录;记录行可展开查看应用/网站排行与被拦网站,记录页可一键导出近 7/30 天 Markdown 报告到「下载」
- **承诺机制**(v2.1):番茄钟专注阶段不可提前结束,只能等休息窗口;连续打卡 🔥 天数展示,断签清零
- **防绕过**(v2.1):锁定期间「系统设置」「活动监视器」强制隐藏,即使在白名单中
- **专注质量**(v2.1):每条记录附质量分(拦截次数、提前结束、强退都会扣分)与拦截次数;记录页有近 7 / 30 天专注趋势图
- **菜单栏常驻**:实时显示 ⏳ 剩余 / ⏱ 已专注 / ☕ 休息倒计时,下拉查看今日统计与连续天数
- 秒级当前时间大时钟、学习任务备注、本地专注记录和今日统计
- 自动扫描已安装应用并保存白名单;Finder、Dock 等关键系统进程始终受保护
- 手动锁定开关(不开会话也能锁)

## 使用

1. 双击 `build/StudyLock.app`(或安装到 `/Applications`)。
2. 在「白名单」中勾选学习时需要使用的应用;可切到「网站」页添加专注期间允许访问的域名(其余网页会被拦截)。
3. 返回「专注」,选择模式与参数,开始学习。

## 构建

需要 macOS 13+ 与 Swift 工具链:

```bash
./build-app.sh
```

**macOS 26 起需要完整 Xcode**(不能只装 Command Line Tools):新 SDK 里 SwiftUI 的
`@State` 等已改为宏,编译要用 `libSwiftUIMacros.dylib`,而该插件只随 Xcode 分发。
只装 CLT 会冒出几十条 `cannot find '$xxx' in scope`,真正的根因是那条不起眼的
`plugin for module 'SwiftUIMacros' not found`。`build-app.sh` 会自动检测并切换到已装的
Xcode(`/Applications/Xcode.app` 或 `Xcode-beta.app`),无需改 `xcode-select`。

运行测试(swift-testing):

```bash
swift test
```

## 系统边界

这是用户态自律工具,不是家长控制或 MDM。刻意保留的紧急出口与已知边界:

- **强制退出**(Cmd+Opt+Esc)、注销或重启电脑仍可绕过锁定——但会被记为污点,加长后续冷静期,未完成会话在下次启动时恢复或记为强退。
- **网站白名单在浏览器层实现**:每 2 秒扫描 Safari/Chrome/Edge/Arc/Brave/Vivaldi(含 Beta/Dev/Canary)的所有标签,非白名单网页清空。这样能兼容任何代理/VPN,但仅覆盖这几款可脚本化浏览器;换用不受支持的浏览器可绕过(不过非白名单**应用**本身已被隐藏,除非把该浏览器也加进应用白名单)。需要「自动化」权限,拒绝授权则网页检查失效(会有横幅提示)。
  - 为什么不做"整机网络层默认断网":那需要在系统代理/VPN 之下拦截流量。若开着 Clash TUN 模式或 WARP 等,全部流量在 IP 层被 VPN 接管,用户态 App 无法在其下过滤——除非拿到苹果 NetworkExtension 授权(自签 App 不可用)。因此改用浏览器层方案,反而不受你的 VPN 影响。
- v2.1 的 `/etc/hosts` 黑名单与 v2.3 的系统代理接管均已退役;若系统留有旧残留,应用启动时会自动清理(hosts 需一次管理员密码,代理设置自动还原)。
- 需要不可绕过的限制时,请使用 macOS 屏幕使用时间或组织管理的 MDM 配置。

## macOS 26/27 上的两条性能红线

升级 macOS 27 后曾出现「一开专注整机卡顿」,根因是两处与新系统交互的放大效应,改动时勿回退:

- **AppleScript 绝不能在主线程同步执行**。NSAppleScript 等 Apple 事件回复时会驱动一个嵌套
  Carbon 事件循环,一秒转几百圈;而 macOS 26 起菜单栏项由 MenuBarAgent 以 scene 托管,每次
  CoreAnimation 提交都要向渲染服务器同步申请栅栏(阻塞式 mach_msg)。两者相乘会把主线程占死、
  WindowServer 打满。现全部走 `AppleScriptRunner` 的专用线程。顺带把扫描脚本从「每标签一次
  Apple 事件」改成「每窗口一次」(8 个标签实测 0.56s → 0.18s,差距随标签数线性拉大)。
- **不要用 SwiftUI 的 `MenuBarExtra`**。在 macOS 26/27 上它会自激:每次 CA 提交都重设一次状态栏项
  内容框并同步要栅栏,**与内容无关**——实测把标签换成完全静态的图标后开销分毫不减,主线程约 30%
  时间阻塞于此;整个删掉后归零。现改用原生 `NSStatusItem`(见 `StatusItemController`)。
